# Admin tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Admin tab in the organiser app for the single `role = 'admin'` account: manage organisers, see and edit any organiser's events, reopen finalized events, unpublish/unlist any event, and set the public retention numbers. An admin has every Pro-level access plus the Admin tab.

**Architecture:** `requireAdmin` guards new `api/admin/*` endpoints; `api/tournaments/[id].js` stops scoping by owner for admins; a `site_settings` table holds two retention numbers which the viewer reads through a new read-only view; the Admin screens are a new classic script `admin-ui.js` rendered into `#stageArea` by `index.html`. Built on organiser accounts (commit 881b81b) and the finalize feature.

**Tech Stack:** Vercel serverless functions (CommonJS), Neon Postgres tagged-template `sql` from `api/_lib/db.js`, vanilla JS organiser (`index.html` + classic scripts like `pods-ui.js`), the separate `viewer/` Vercel project, Node `node --test`. No new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-14-admin-tab-design.md` (read it first; it is the binding authority, this plan argues from it).

## Global Constraints

- Real DartConnect player names must never enter the repo.
- Do NOT run `git add`, `git commit`, `git push`, `git stash`, `git checkout` or any git write command. The controller reviews the working tree and commits. Leave `.claude/` and `docs/superpowers/specs/2026-10-13-csv-export-design.md` alone. Never revert uncommitted files that are not yours.
- Tests: `npm test` must keep passing (686 before this work); `npm run check-viewer` must stay ok (you should not need to touch `render.js`/`render.css`).
- No new npm dependencies. CommonJS in `api/`. Match surrounding style (2-space indent, single quotes, `sql\`...\`` tagged templates, early `return` after `res.status(...).json(...)`). Existing files keep their line endings; use the Edit tool for existing files.
- Roles exactly `'organizer'` / `'admin'`; tiers `'basic'` / `'pro'`. All text coming from the database (names, emails, event names) is escaped with the organiser's `escapeHtml` wherever it is put into HTML.
- Admin endpoints are server-enforced: every `api/admin/*` handler starts with `const admin = await requireAdmin(req, res); if (!admin) return;`. In the shared-Public fallback (`REQUIRE_LOGIN` not `true`) nobody is an admin, so they answer 403.
- Settings defaults: `resultsDays` 14 (allowed 1-90), `liveHours` 48 (allowed 1-168). No audit log.
- The finalized lock in `api/tournaments/[id].js` is not bypassed for admins; they use the explicit Reopen action.
- Real Postgres is not available here: keep every new SQL statement simple and readable, and list new statements in your report so the controller can check them on a scratch Neon branch.

## Review Focus

- Every `/api/admin/*` route enforces admin server-side (no reliance on the hidden sidebar entry); suspended admin, stale-session admin and non-admin are rejected.
- An admin can never lock the service out of administrators: last admin, own role change, own suspension, own deletion.
- Transfers and deletes never orphan or lose events; `finalized` survives a transfer; deleting an organiser who owns events is refused.
- Reopen / unpublish / unlist change exactly what they say; an organiser's open tab then gets the normal 409 and not corrupted data.
- Viewer keeps working with `site_settings` / `public_settings` missing, malformed or extreme; the widened query window respects `MAX_ROWS`.
- Admin sees Pro access whatever the stored tier says (entry limit, `/api/auth/me`, top bar), and no Pro gating reads the raw column.
- Text from other organisers is escaped in every Admin view.

### Task 2: Organisers API

**Files:**

**Interfaces:**
- Consumes: Task 1 (`requireAdmin`, `effectiveTier`), accounts helpers (`createOrganizer`, `issueToken`, `sendMail`, `isMailConfigured`, `appUrl`, `normalizeEmail`, `findByEmail`, `findById`).
- Produces (JSON; 405 for other methods; the public shared row `public@dartdraw.local` never appears and can never be targeted: 404):
  - `GET /api/admin/organizers` -> `{ organizers: [{ id, email, name, role, tier, effectiveTier, suspended, verified, createdAt, eventCount }] }`, newest first.
  - `POST /api/admin/organizers` `{ name, email, tier }` -> 201 `{ organizer, link }`: validates (name 1-80 chars, email shape <= 254, tier `basic|pro`), 409 `{ error: 'An account with that email already exists.' }`; creates a verified account with an unusable password (`'disabled'` hash) and an `invite` token; `link` is `appUrl(req) + '/reset.html?token=' + raw`; emails the link too when `isMailConfigured()` (never fail the request if mail fails).
  - `PATCH /api/admin/organizers/:id` `{ tier?, role?, suspended? }` -> `{ organizer }`; guards (409 with a clear message): the caller cannot change their own role or suspend themselves; the last active admin cannot be demoted or suspended; at least one field required (400); invalid values 400; suspending or demoting bumps `token_version` (old sessions die). Promoting someone to admin requires them to be verified (409 otherwise).
  - `POST /api/admin/organizers/:id/reset-link` -> `{ link }` (a `reset` token; also emailed when mail is configured); 404 for the Public row or unknown id.
  - `POST /api/admin/organizers/:id/transfer` `{ toOrganizerId }` -> `{ moved }`: one `UPDATE tournaments SET created_by = <target> WHERE created_by = <source> RETURNING id`; target must exist, not be the Public row, not be suspended, and differ from the source (400/404/409 as appropriate); `finalized` and every other field of the events untouched; `updated_at` untouched.
  - `DELETE /api/admin/organizers/:id` -> 204; refused with 409 `{ error: 'Transfer or delete their events first.', eventCount }` while they own events; never the caller, never the last admin, never the Public row (404).

**Interfaces:**
- Consumes: Tasks 1-2.
- Produces:
  - `migrations/2026-10-14-admin.sql` (idempotent): `CREATE TABLE IF NOT EXISTS site_settings (key text PRIMARY KEY, value jsonb NOT NULL, updated_at timestamptz NOT NULL DEFAULT now());`
  - `api/_lib/settings.js`: `DEFAULT_SETTINGS = { resultsDays: 14, liveHours: 48 }`, `SETTING_LIMITS = { resultsDays: [1, 90], liveHours: [1, 168] }`, `async getSettings()` -> `{ resultsDays, liveHours }` (missing rows or a missing table -> defaults; junk values -> defaults; never throws), `validateSettings(body)` -> `{ ok: true, value }` or `{ ok: false, error }` (both integers within limits).
  - `GET /api/admin/settings` -> `{ resultsDays, liveHours, limits }`; `PUT /api/admin/settings` `{ resultsDays, liveHours }` -> same shape; upserts the two keys (`INSERT ... ON CONFLICT (key) DO UPDATE`); 400 on invalid.
  - `GET /api/admin/events?q=&owner=&limit=&offset=` -> `{ events: [{ id, tournamentName, eventName, owner: { id, name, email }, format, date, published, listed, finalizedAt, updatedAt }], total }`, newest first, `limit` default 50 max 100, `q` matches tournament/event name or owner name/email case-insensitively, `owner` filters by organiser id. The SQL must select only those fields (jsonb path extraction), never the whole `data` column.
  - `POST /api/admin/events/:id` `{ action, toOrganizerId? }` with `action` in `reopen` (removes `finalized` and sets `updated_at = now()`; 409 `{ error: 'Event is not finalized.' }` if it is not), `unpublish` (published=false and listed=false), `unlist` (listed=false), `transfer` (moves this one event; same target rules as Task 2), `delete` (permanent, allowed even when finalized) -> `{ event }` summary (or `{ ok: true }` for delete); unknown action 400; unknown id 404. These never change anything else in `data`; each bumps `updated_at` except `transfer`.
